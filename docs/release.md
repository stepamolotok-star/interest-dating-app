# Подпись и выпуск приложения

## Имя пакета

`ru.barakhtinsa.app` — постоянное. После публикации в RuStore его не поменять: другое имя — это другое приложение. С названием на экране оно не связано: название можно менять сколько угодно.

Схема возврата из входа через Яндекс ID — `ru.barakhtinsa.app://oauth/yandex`; её указывают при регистрации приложения в Яндекс ID.

## Ключ подписи

Создан 21.11.2026: RSA 4096, действует до 13.11.2056, псевдоним `release`, владелец `CN=BarakhtinSA, C=RU`.

Отпечатки сертификата — их спрашивают RuStore и верификация разработчика Google:

- SHA-256: `FD:CE:38:F4:DB:58:13:9C:B0:0E:64:5C:AA:03:E8:27:1F:96:02:18:7D:CE:B9:91:C2:A8:CA:4E:9D:E9:66:AD`
- SHA-1: `88:9B:27:9D:89:9F:B3:D8:DB:97:AD:09:4E:CA:D5:A1:FE:9D:BF:1F`

Сам ключ (`.jks`) и пароль в репозитории не хранятся и храниться не должны. Владелец держит две копии в разных местах. Потерян ключ — новые версии нельзя будет поставить поверх старых; утёк — кто-то сможет выпускать «обновления» от вашего имени.

## Как собрать подписанный APK

Положите рядом с проектом файл `mobile/android/key.properties` (git его не берёт):

```
storeFile=/полный/путь/к/barakhtinsa-release.jks
storePassword=пароль
```

Затем `flutter build apk --release` с нужными параметрами (`--dart-define=API_URL=…`, данные оператора — см. `docs/legal-notes.md`). Без `key.properties` сборка подпишется отладочным ключом и предупредит об этом — такой APK для RuStore не годится.

Проверить подпись: `apksigner verify --print-certs app-release.apk` — должен быть `CN=BarakhtinSA` и SHA-256 выше.
